# Hermes Agent 部署：从安装到飞书机器人上线

> 从零部署 Hermes Agent：装完本体、配好模型，接上中文文档 MCP，最后把飞书机器人跑起来，手机发消息就能指挥它干活。

## 一、Hermes 是什么

Hermes Agent 是 Nous Research 开源的 AI Agent，和 Claude Code、Codex 同类，但不止于终端——同一套核心可以跑在 CLI、桌面应用、飞书 / Telegram / Discord 等 20 多个消息平台上，飞书里就是一个能打字、能调工具的机器人。

几个和别的 Agent 不太一样的地方：

| 特性 | 说明 |
| ---- | ---- |
| 技能自进化 | 干过一次的复杂流程能存成 skill，下次直接复用 |
| 持久记忆 | 跨会话记住你的偏好、环境、踩过的坑 |
| 多渠道网关 | 一个 agent 同时挂在飞书、Telegram、Discord…全工具访问 |
| 模型无关 | OpenRouter / DeepSeek / 通义 / 本地模型，随便换 |

## 二、部署前准备

- Linux / macOS / WSL2，本机 Debian 13
- 网络能访问 GitHub（或使用中文社区镜像）

国内网络建议直接用中文社区镜像，速度和稳定性都好一些：

```
https://res1.hermesagent.org.cn/install.sh
```

## 三、安装

```bash
# 官方源
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# 或中文社区镜像
curl -fsSL https://res1.hermesagent.org.cn/install.sh | bash
```

安装脚本会自动装 uv、Python、venv 和启动器。装完验证：

```bash
hermes --version
hermes doctor   # 环境自检
```

## 四、初始化配置

```bash
hermes setup    # 交互向导：选模型 Provider、填 API Key
hermes model    # 随时切换模型
```

两条规矩记牢：

- **密钥只放 `~/.hermes/.env`**，比如 `DEEPSEEK_API_KEY=***
- **非密钥配置走 `hermes config set`**，不要手改 `config.yaml`，缩进错了整个网关会挂

常用配置：

```bash
hermes config set model deepseek-chat
hermes config set display.interface tui   # 终端 UI
```

## 五、接入中文文档 MCP

中文社区维护的文档服务器，Streamable HTTP，不需要 API Key、不用登录：

```
https://mcp.hermesagent.org.cn/v1
```

### 5.1 先装 MCP SDK

Hermes 的 venv 默认没带 `mcp` 包，没装的话原生 MCP 客户端会**静默禁用**——配了服务器也不生效，还不报错。先装上：

```bash
uv pip install --python /usr/local/lib/hermes-agent/venv/bin/python mcp
```

路径按自己机器的实际安装位置改，`which hermes` 能查到。

### 5.2 加服务器

编辑 `~/.hermes/config.yaml`：

```yaml
mcp_servers:
  hermes-docs-zh:
    url: "https://mcp.hermesagent.org.cn/v1"
```

懒得手改的话，把这句话直接发给 Hermes，它自己会改：

> 请把这个 Hermes 中文文档 MCP server 加到你的配置里：https://mcp.hermesagent.org.cn/v1（Streamable HTTP，无需 API Key、无需登录）

### 5.3 重启生效

MCP 工具是启动时才注册的，改完配置要重开一个会话。起来后多三个工具：

- `mcp_hermes_docs_zh_search_docs` — 关键词检索文档
- `mcp_hermes_docs_zh_get_doc` — 按 permalink 读全文
- `mcp_hermes_docs_zh_list_recent_releases` — 最近版本

### 5.4 验证

直接让它查点东西，能返回就算通了：

> 用中文文档查一下安装步骤

后面接飞书、配网关都能让它查文档，不用翻英文站。

## 六、接入飞书

### 6.1 飞书开放平台建应用

1. 打开 [open.feishu.cn](https://open.feishu.cn)，创建**企业自建应用**
2. 拿到两个凭据：
   - **App ID**（`cli_` 开头）
   - **App Secret**
3. 应用里开启**机器人**能力
4. 权限管理里开通：
   - `im:message`（读取消息）
   - `im:message:send_as_bot`（以机器人身份发消息）
   - `im:chat`（群信息，可选）
5. 发布版本并**申请上线**（企业自建应用要管理员审核，个人开发者邮箱能直接过）

### 6.2 Hermes 侧配凭据

把凭据写进 `~/.hermes/.env`：

```bash
FEISHU_APP_ID=cli_xxxx
FEISHU_APP_SECRET=***
FEISHU_DOMAIN=feishu
FEISHU_CONNECTION_MODE=websocket
```

> `FEISHU_DOMAIN`：国内版 `feishu`，国际版 `lark`
> `websocket` 模式是 Hermes 主动连飞书，不需要公网地址和回调 URL，个人服务器首选

### 6.3 装网关服务

```bash
hermes gateway install --system --run-as-user root --start-now
hermes gateway status --system
```

**坑（容器环境必看）**：LXC / 容器里没有 user systemd bus，直接 `hermes gateway install` 会报 "Failed to connect to user scope bus"。必须用 `--system`。另外 `install --system` 可能自动把服务检测到宿主用户（比如 `zhaizz`）的 home 下，导致网关读错 `.env`。症状是服务"running"但日志显示 `No messaging platforms enabled`。修正：

```bash
# 看服务实际用的 home
tr '\0' '\n' < /proc/<pid>/environ | grep -E 'HERMES|FEISHU'

# 改服务文件指向真实 HERMES_HOME
sudo sed -i 's|/home/zhaizz/.hermes|/root/.hermes|g' /etc/systemd/system/hermes-gateway.service
sudo systemctl daemon-reload && sudo systemctl restart hermes-gateway
```

### 6.4 配对

新用户第一条消息会被网关拦截，生成配对请求：

```bash
hermes pairing list      # 看待批准请求
hermes pairing approve   # 批准
```

或者飞书机器人直接发消息给你，然后批准对应 open_id。

### 6.5 验证

```bash
journalctl -u hermes-gateway -f
```

看到这行就通了：

```
[Lark] [INFO] connected to wss://msg-frontier.feishu.cn/ws/v2?...
```

然后飞书里给机器人发条消息，正常回复即全流程打通。

## 七、日常使用

| 场景 | 命令 |
| ---- | ---- |
| 对话 | `hermes` / `hermes chat -q "问题"` |
| 定时任务 | 会话里说"每天早上 9 点推送…" |
| 技能管理 | 会话里让它把流程存成 skill |
| 多平台 | 同一个 `.env` 加 `TELEGRAM_BOT_TOKEN=*** 重启即挂 |

## 八、踩坑记录

| 坑 | 现象 | 解法 |
| ---- | ---- | ---- |
| venv 没装 mcp 包 | 配了 MCP 服务器但工具不出现，无报错 | `uv pip install --python <venv路径> mcp` |
| 容器无 user systemd bus | `gateway install` 报 bus 连接失败 | 用 `--system` |
| 网关读错 profile | 服务 running 但日志 `No messaging platforms enabled` | `sed -i` 修正 unit 的 HERMES_HOME 后 daemon-reload |
| 配对不生效 | 发消息无回复 | `journalctl` 看日志，`hermes pairing list` 检查待批准请求 |

## 九、升级与卸载

```bash
# 升级
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# 卸载
hermes gateway uninstall --system
rm -rf ~/.hermes
```

## 十、其他消息平台

飞书只是其中之一，Telegram / Discord / Slack / WhatsApp 等平台的接入方式大同小异，都是拿凭据填 `.env`、重启网关。更多平台的接入方法可以到 Hermes 中文社区查看：[消息平台接入文档](https://hermesagent.org.cn/docs/user-guide/messaging)。
