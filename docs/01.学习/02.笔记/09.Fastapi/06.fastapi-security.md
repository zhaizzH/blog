# FastAPI 安全认证 OAuth2 与 JWT

> 用 OAuth2 密码流 + JWT 给接口加上登录：`OAuth2PasswordBearer` 从请求头取令牌，`get_current_user` 把令牌变成用户，`/token` 端点用表单收密码、签发 JWT。整套跑通后，Swagger 的 Authorize 按钮直接能用。

## 一、安全总览

### 1.1 为什么安全这么难

安全规范又多又绕，术语互相打架。FastAPI 的思路：按标准封装好常用工具，直接拿来用。

OAuth2 定义了多种处理身份认证和授权的方式，"使用 Facebook / Google / GitHub 登录"的网站背后都是这套机制。FastAPI 只用其中一种流程：`password` 流，适合后端和认证在同一个应用。

### 1.2 OpenID Connect 与 OpenID

OpenID Connect 建立在 OAuth2 之上，让各家实现能互通。Google 登录用的就是 OpenID Connect（底层是 OAuth2）；Facebook 登录不支持，用的是自己风格的 OAuth2。名词对照：OAuth2（广泛使用）、OpenID Connect（基于 OAuth2，Google 用它）、OpenID（独立规范，已不流行）。

### 1.3 OpenAPI 安全方案

OpenAPI（以前的 Swagger）定义了几种标准安全方案，FastAPI 能把它们自动集成进交互式文档：`apiKey`（应用专属密钥，可来自查询参数、请求头或 cookie）、`http`（标准 HTTP 认证：`bearer`、Basic、Digest）、`oauth2`（各种流程：`implicit`、`clientCredentials`、`authorizationCode`、`password`）、`openIdConnect`（定义如何自动发现 OAuth2 认证数据）。

其中 `implicit`、`clientCredentials`、`authorizationCode` 适合用来**搭建身份认证服务商**（像 Google、GitHub 那样给别人提供登录）。而 `password` 流完美适配"同一个应用既做 API 又做认证"的场景，接下来全是它的实战。

### 1.4 fastapi.security 工具

`fastapi.security` 给每种安全方案都备了工具，且**自动集成到 Swagger 文档**——出现 Authorize 按钮，能在线输入用户名密码测试。

## 二、OAuth2 密码流

### 2.1 安装 python-multipart

OAuth2 密码流要求 `username` 和 `password` 以**表单数据**发送，解析表单需要底层库：

```console
$ pip install python-multipart
```

`fastapi[standard]` 会自动带上，普通安装不会。

### 2.2 最小示例：OAuth2PasswordBearer

三四行代码就能让接口要求登录：

```python
from typing import Annotated
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")


@app.get("/items/")
async def read_items(token: Annotated[str, Depends(oauth2_scheme)]):
    return {"token": token}
```

`OAuth2PasswordBearer(tokenUrl="token")` 是安全工具的实例，它本身可调用，所以能直接塞进 `Depends`。两个容易误解的点：

- `tokenUrl="token"` 只是**声明**客户端应该去 `/token` 换令牌，并不会创建这个端点——对应的路径操作后面自己写
- 用的是相对 URL，部署在子路径或代理后面依然正确（API 在 `/api/v1/` 下就指向 `/api/v1/token`）

`Depends(oauth2_scheme)` 后 FastAPI 自动找 `Authorization` 请求头，检查值是不是 `Bearer ` 加一串令牌；是就把令牌作为 `str` 注入，没有或格式不对直接 401，函数能执行 `token` 就一定是字符串。跑起来打开 `/docs`，右上角出现 **Authorize** 按钮——点开能输入用户名密码，不过现在输什么都不会生效，校验逻辑还没写。它不是给最终用户用的前端，而是给前端团队、第三方系统和自己调试用的自动化工具。

### 2.3 password 流完整链路

`password` 流适合"API 和认证在同一个应用"的场景：前端表单 POST `username`/`password` 到 `tokenUrl`，API 校验后返回令牌；前端存起来，之后每个请求带 `Authorization: Bearer <token>` 头。令牌会过期，得重新登录——被偷也不会永久有效。
## 三、获取当前用户

### 3.1 用户模型与 get_current_user

上一章拿到的只是一串 token 字符串。这一章把 token 加工成用户对象。和请求体一样用 Pydantic 定义 `User`（`username` 必填，`email`、`full_name`、`disabled` 可选）。依赖可以套娃：`get_current_user` 把 `oauth2_scheme` 当子依赖，拿到 token 字符串，再加工成用户对象：

```python
class User(BaseModel):
    username: str
    email: str | None = None
    full_name: str | None = None
    disabled: bool | None = None


def fake_decode_token(token):
    return User(username=token + "fakedecoded", email="john@example.com", full_name="John Doe")


async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    return fake_decode_token(token)
```

`fake_decode_token` 是假的解码函数——真正的 JWT 解码在后面，现在只是把 token 拼进 username，假装"解码"了一下。子依赖的写法跟之前路径操作里直接用 `oauth2_scheme` 完全一样，只是换了个地方。

### 3.2 路径操作里注入当前用户

路径操作里 `current_user: Annotated[User, Depends(get_current_user)]` 三行就能拿到当前用户，标注成 `User` 类型后编辑器有补全和类型检查。依赖的调用链：`read_users_me` → `get_current_user` → `oauth2_scheme`，每一层只做一件事，出问题能精确定位在哪一环。

依赖注入让安全机制和具体模型解耦：改模型、换返回值类型都行。关键是：**安全和依赖注入的代码只需要写一次**，之后几千个端点全部复用同一个安全系统。各层职责：

| 层 | 职责 |
| ---- | ---- |
| `oauth2_scheme` | 从请求头取 token，没有就 401 |
| `get_current_user` | 把 token 变成 User 对象 |
| 路径操作 | 直接消费 User，安全细节不用管 |

## 四、完整登录流程

### 4.1 表单字段规范

OAuth2 规定密码流以**表单数据**（不是 JSON）发送 `username`/`password`，字段名不能改。

`OAuth2PasswordRequestForm` 只是普通类依赖，不会出现在 OpenAPI 安全方案里。

### 4.2 登录端点：查用户、比密码、发令牌

```python
fake_users_db = {
    "johndoe": {"username": "johndoe", "hashed_password": "fakehashedsecret", "disabled": False},
    "alice": {"username": "alice", "hashed_password": "fakehashedsecret2", "disabled": True},
}


@app.post("/token")
async def login(form_data: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user_dict = fake_users_db.get(form_data.username)
    if not user_dict or "fakehashed" + form_data.password != user_dict["hashed_password"]:
        raise HTTPException(status_code=400, detail="Incorrect username or password")
    return {"access_token": user_dict["username"], "token_type": "bearer"}
```

几个细节：

- 用户不存在和密码错误返回**同样的**错误信息，避免泄露"这个用户名存在"；官方示例用 `UserInDB(User)` 继承用户模型加 `hashed_password` 字段再展开，效果一样
- 密码比较用的是 `"fakehashed" + 明文` 的伪哈希，只是教学演示，**绝对不能用于生产**；响应键名 `access_token`、`token_type` 是规范规定的

### 4.3 激活用户校验

再加一层 `get_current_active_user` 套在 `get_current_user` 外，禁用用户直接 400。401 响应带 `WWW-Authenticate: Bearer` 头是规范的一部分。

### 4.4 在文档里试一把

授权后 `/users/me` 正常，不授权 401，禁用用户 400。流程完整了，但令牌就是用户名本身，谁都能伪造。

## 五、JWT 令牌与密码哈希

### 5.1 JWT 是什么

JWT（JSON Web Tokens）把一段 JSON 编码成一长串没有空格的字符串，看起来像 `eyJhbG...sw5c`。两个关键特性：**不加密**（任何人都能解码看内容，别塞敏感信息）、**有签名**（密钥签过名，改一个字节验证立刻失败）。签发一个有效期一周的令牌，用户带着回来，你能确认是你签发的、还没过期。

### 5.2 安装依赖

```console
$ pip install pyjwt
$ pip install "pwdlib[argon2]"
```

`pyjwt` 签发/校验 JWT，`pwdlib` 做密码哈希（推荐 Argon2）。RSA/ECDSA 签名要装 `pyjwt[crypto]`。

### 5.3 密码哈希与校验

`password_hash = PasswordHash.recommended()` 创建哈希器，`verify_password(plain, hashed)` 就是 `password_hash.verify` 的封装，`DUMMY_HASH` 是预先生成的假哈希。数据库里存的 `hashed_password` 不再是 `fakehashedsecret`，而是类似 `$argon2id$v=19$m=65536,t=3,p=4$wagCPX...` 的哈希串。`authenticate_user` 有个防**时序攻击**的细节：用户名不存在时也对 `DUMMY_HASH` 跑一次 `verify_password`，响应时间不随用户名存在与否变化，攻击者没法靠响应快慢枚举已注册的用户名：

```python
def authenticate_user(fake_db, username: str, password: str):
    user = get_user(fake_db, username)
    if not user:
        verify_password(password, DUMMY_HASH)  # 防时序攻击
        return False
    return user if verify_password(password, user.hashed_password) else False
```

### 5.4 签发 JWT

密钥不能写死，用 `openssl rand -hex 32` 生成随机值：

```python
SECRET_KEY = "09d25e094faa6ca2556c818166b7a9563b93f7099f6f0f4caa6cf63b88e8d3e7"  # 换成自己生成的
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30


def create_access_token(data: dict, expires_delta: timedelta | None = None):
    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + (expires_delta or timedelta(minutes=15))
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
```

`exp` 是过期时间戳，`sub` 是主题（用户标识），写成 `username:johndoe` 带前缀保证唯一——用户、车、文章可能撞 ID。

### 5.5 解码校验令牌

`get_current_user` 升级：解出 payload → 取 `sub` → 查用户。任何一步不对，都抛 401：

```python
async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username = payload.get("sub")
        user = get_user(fake_users_db, username=username) if username else None
    except InvalidTokenError:
        user = None
    if user is None:
        raise HTTPException(status_code=401, detail="Could not validate credentials", headers={"WWW-Authenticate": "Bearer"})
    return user
```

`jwt.decode` 一次干三件事：校验签名、检查过期时间、解析 payload，签名不对或过期都会抛 `InvalidTokenError`，统一转成 401。官方示例用 `TokenData` 模型装解析结果再查库，这里直接判空，效果一样。

### 5.6 登录端点签发真令牌

登录端点把伪哈希换成 `authenticate_user` + `create_access_token`，校验失败抛 401（带 `WWW-Authenticate: Bearer` 头），成功就返回 `Token(access_token=create_access_token(data={"sub": user.username}, expires_delta=timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)), token_type="bearer")`。

用 `johndoe` / `secret` 授权后调 `/users/me/` 能拿到用户数据；请求头里只有 `Authorization: Bearer eyJhbG...`，数据库里也不存明文密码，只有哈希。

安全主线到此走完：表单收密码 → 哈希校验 → 签发 JWT → 请求头带 Bearer → 解码取用户。想支持细粒度权限，可以去高级用户指南学 OAuth2 的 `scopes`。
