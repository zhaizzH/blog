# FastAPI 响应与错误处理

> 接口的「出口」和「异常」两件事：响应模型决定返回什么、过滤掉不该泄露的字段，状态码表达语义，`HTTPException` 表达错误，装饰器参数整理文档，`jsonable_encoder` 兜底序列化。

## 一、响应模型

### 1.1 返回类型注解

给路径操作函数加返回类型注解，FastAPI 就把该类型当响应模型：

```python
class Item(BaseModel):
    name: str
    price: float

@app.post("/items/")
async def create_item(item: Item) -> Item:
    return item
```

声明后自动做四件事：校验（数据不符模型就报 500）、JSON Schema（自动文档用）、序列化（Pydantic 转 JSON）、过滤（只输出声明过的字段，多余的丢掉）。过滤最值钱，是安全性的关键。

### 1.2 response_model 参数

函数返回 dict / 数据库对象、想按某个 Pydantic 模型输出时，写返回类型注解编辑器会报类型不匹配，改用装饰器参数 `response_model`：`@app.post("/items/", response_model=Item)`。它是装饰器参数，不是函数参数；和返回类型注解同时出现时它优先；`response_model=None` 可禁用。

## 二、多模型拆分

输入输出**共用同一个模型**是经典事故：`UserIn` 带明文密码，又拿它当响应模型，密码就原样返回了——被别的接口复用时，等于把密码发给所有客户端。所以同一个实体要按场景拆成多个模型。

### 2.1 一个用户，三种模型

输入要收明文密码、输出不能带密码、存库的是哈希。拆成三个模型，各管一段：

```python
class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr

class UserOut(BaseModel):
    username: str
    email: EmailStr

class UserInDB(BaseModel):
    username: str
    hashed_password: str
    email: EmailStr

def fake_save_user(user_in: UserIn):
    hashed = "supersecret" + user_in.password
    return UserInDB(**user_in.model_dump(), hashed_password=hashed)

@app.post("/user/", response_model=UserOut)
async def create_user(user_in: UserIn):
    return fake_save_user(user_in)
```

数据流：收 `UserIn`（明文密码）→ 哈希存成 `UserInDB` → 按 `response_model=UserOut` 过滤返回，密码在哪个环节都不出接口。

::: danger 危险
`"supersecret" + password` 只是演示用的假哈希，没有安全性。真实项目用 bcrypt 之类只存哈希。
:::

### 2.2 核心语法：`**user_in.model_dump()`

`model_dump()` 把模型转成普通 dict，`**` 把键值展开成关键字参数，再追加 `hashed_password=...`，就完成了「把 UserIn 数据搬进 UserInDB 并换掉密码字段」：`UserInDB(**user_in.model_dump(), hashed_password="supersecret")`。dict 里有啥传啥，以后加字段不用改这行。

### 2.3 继承消灭重复

三个模型字段高度重叠，重复写三遍是 bug 温床。抽 `UserBase` 基类，子类只写差异：

```python
class UserBase(BaseModel):
    username: str
    email: EmailStr

class UserIn(UserBase):
    password: str

class UserOut(UserBase):
    pass

class UserInDB(UserBase):
    hashed_password: str
```

| 模型 | 差异字段 |
| ---- | ---- |
| UserIn | `password`（明文，输入用） |
| UserOut | 无（输出用） |
| UserInDB | `hashed_password`（存库用） |

继承的字段照样参与校验、转换、文档生成。

### 2.4 列表、dict 与默认值

对象列表用 `response_model=list[Item]`，返回 dict 列表即可；字段名事先不确定时（如关键词权重表），直接用 `dict[str, float]`。响应模型还能声明成「这些类型中的任意一个」（OpenAPI 的 `anyOf`），如 `response_model=PlaneItem | CarItem`——这是参数值不是类型注解，Python 3.10 的 `|` 当表达式用要写成 `typing.Union`。

字段带默认值时响应会全带上，没实际存过的字段也塞满默认值。`response_model_exclude_unset=True` 只返回显式设置过的字段；值恰好等于默认值但被显式写过，照样进响应——Pydantic 分得清「显式设置」和「取自默认值」。同类参数还有 `exclude_defaults`、`exclude_none`；临时去掉几个字段用 `response_model_include` / `response_model_exclude` 传字段名 `set`。省事，但文档里的 JSON Schema 仍是完整模型，字段取舍优先用「多模型 + 继承」。

## 三、响应状态码

### 3.1 status_code 参数

和 `response_model` 一样，`status_code` 也是装饰器（`@app.get()`、`@app.post()` 等）的参数，不是函数参数。默认所有接口都是 200，想改就在装饰器里声明：

```python
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/items/", status_code=status.HTTP_201_CREATED)
async def create_item(name: str):
    return {"name": name}
```

`201` 表示「已创建」，创建资源类接口的标准语义。FastAPI 实际响应时带上这个状态码，也在 OpenAPI 文档里记录，Swagger 界面直接展示。`status_code` 也接收 `IntEnum`，如 `http.HTTPStatus.CREATED`。

### 3.2 状态码速览

常见区间：

| 区间 | 含义 | 常用值 |
| ---- | ---- | ---- |
| 区间 | 含义 | 常用值 |
| ---- | ---- | ---- |
| 1xx | 信息类，几乎不用 | — |
| 2xx | 成功 | `200`、`201`、`204` |
| 3xx | 重定向 | `304` |
| 4xx | 客户端错误 | `400`、`404` |
| 5xx | 服务器错误 | 应用崩了自动返回 |

`204` 表示成功但无内容返回，响应**不能带响应体**，FastAPI 会自动生成「无响应体」文档。

### 3.3 fastapi.status 常量

数字记起来费劲，用 `fastapi.status` 的具名常量，编辑器敲 `status.HTTP_` 自动补全：

| 常量 | 数字 | 场景 |
| ---- | ---- | ---- |
| 常量 | 数字 | 场景 |
| ---- | ---- | ---- |
| `HTTP_200_OK` | 200 | 默认成功 |
| `HTTP_201_CREATED` | 201 | 创建资源 |
| `HTTP_204_NO_CONTENT` | 204 | 删除成功 |
| `HTTP_400_BAD_REQUEST` | 400 | 请求不合法 |
| `HTTP_404_NOT_FOUND` | 404 | 资源不存在 |

::: info 提示
`fastapi.status` 的内容和 `starlette.status` 完全一样（FastAPI 直接复用的 Starlette），用哪个都行，统一就行。
:::

`status_code` 声明的是这个接口的**默认**状态码，一个接口在不同分支返回不同状态码时，得运行时手动改——那是高级篇的内容。

## 四、错误处理

### 4.1 用 HTTPException 抛错误

没权限、资源不存在这类错误，返回 400 范围的码。`HTTPException` 是普通 Python 异常，**只能 `raise` 不能 `return`**：

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()
items = {"foo": "The Foo Wrestlers"}

@app.get("/items/{item_id}")
async def read_item(item_id: str):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": items[item_id]}
```

`raise` 后请求立刻终止，工具函数里触发也一样。存在返回 200，不存在返回 404 `{"detail": "Item not found"}`。`detail` 可传任何能转 JSON 的值；加自定义响应头用 `headers={"X-Error": "..."}`。

### 4.2 自定义异常处理器

自定义异常（自己或某个库 `raise` 的）用 `@app.exception_handler` 全局处理。处理器收 `request` 和 `exc`，返回响应对象：

```python
from fastapi import Request
from fastapi.responses import JSONResponse

class UnicornException(Exception):
    def __init__(self, name: str):
        self.name = name

@app.exception_handler(UnicornException)
async def unicorn_exception_handler(request: Request, exc: UnicornException):
    return JSONResponse(status_code=418, content={"message": f"Oops! {exc.name} did something. There goes a rainbow..."})
```

接口里 `raise UnicornException(name=name)` 时被接住，返回 418。

### 4.3 覆盖默认异常处理器

FastAPI 自带的 `HTTPException` 和参数校验错误处理器都能换掉。参数不合法触发 `RequestValidationError`，默认返回 JSON，想改纯文本：

```python
from fastapi.exceptions import RequestValidationError
from fastapi.responses import PlainTextResponse

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc: RequestValidationError):
    message = "Validation errors:"
    for error in exc.errors():
        message += f"\nField: {error['loc']}, Error: {error['msg']}"
    return PlainTextResponse(message, status_code=400)
```

`exc.errors()` 是错误列表，每项有 `loc`（位置）和 `msg`（原因）。默认 422，这里改成 400；它还有 `exc.body`（原始请求体），可记录日志。注意错误对象带文件、行号，别直接转字符串返回。

覆盖 `HTTPException` 处理器时注意：FastAPI 的 `HTTPException` 继承自 Starlette 版，区别只在 `detail`——前者接受任意 JSON 兼容数据，后者只收字符串。`raise` 用 FastAPI 的，**注册处理器用 Starlette 的**，Starlette 内部、插件触发的 `HTTPException` 才能被捕获。想保留默认行为，导入默认处理器先干自己的事再转交，如 `request_validation_exception_handler(request, exc)`。

## 五、路径操作配置

`@app.get()` 这些装饰器不光注册路由，还能带一堆配置：标签、摘要、描述、弃用标记，文档立刻变样。

### 5.1 标签 tags

给 `tags` 传字符串列表即可分组：`@app.post("/items/", tags=["items"])`。标签多了收进 `Enum`，写错编译器直接报错。

### 5.2 summary / description / docstring

`summary` 是短标题，`description` 是详细说明。长描述写进 docstring，FastAPI 自动读取且支持 Markdown，注意缩进贴着函数体：

```python
@app.post("/items/", summary="Create an item")
async def create_item(item: Item) -> Item:
    """Create an item: - **name** required - **price** required"""
    return item
```

`response_description` 描述**响应**，`description` 描述**路径操作本身**，别搞混。OpenAPI 规定每个路径操作都要有响应描述，没写时 FastAPI 自动补 "Successful response"。

### 5.3 标记弃用

接口要下线但不删，加 `deprecated=True`，`/docs` 里这个接口被标记为「弃用」，老调用还能继续跑。`@app.get("/elements/", tags=["items"], deprecated=True)` 即可。

::: info 提示
这些参数都传给**路径操作装饰器**（`@app.get(...)`），不是函数本身。
:::

| 参数 | 作用 | 显示位置 |
| ---- | ---- | ---- |
| `status_code` | 响应状态码 | 响应头、文档 |
| `tags` | 接口分组 | 文档 |
| `summary` / `description` | 标题和说明 | 文档 |
| docstring | 长描述（Markdown） | 文档 |
| `response_description` | 响应描述 | 文档 |
| `deprecated` | 弃用标记 | 文档 |

## 六、jsonable_encoder

### 6.1 什么问题

接口返回模型时 FastAPI 自动序列化，但自己写代码存数据时没这待遇：数据库不认 `datetime`、模型实例，得先转 `dict`。手写又啰嗦又漏字段，`jsonable_encoder()` 专干这个。

### 6.2 用 jsonable_encoder

```python
from fastapi.encoders import jsonable_encoder

fake_db[id] = jsonable_encoder(item)
```

传入一个对象（比如 Pydantic 模型），返回 JSON 兼容的版本：模型 → `dict`（含所有字段）、`datetime` → ISO 8601 字符串、`UUID` → 字符串、`bytes` → Base64 字符串。模型字段里的 `datetime` 也会被递归处理——`jsonable_encoder` 会遍历整个数据结构，把每个不兼容的值都转掉。

### 6.3 什么时候用得上

- 存数据库/ORM：得到纯 `dict` 直接入库
- 发 Redis 缓存：序列化前先转一遍，避免类型炸
- 错误处理拼响应：`exc.errors()` 里可能有非 JSON 兼容值，包一层再返回

::: info 提示
`jsonable_encoder` 是 FastAPI 内部把模型、`datetime` 转成 JSON 兼容对象的工具，返回的还是 Python 对象，字符串化是 `json.dumps` 的事。
:::
