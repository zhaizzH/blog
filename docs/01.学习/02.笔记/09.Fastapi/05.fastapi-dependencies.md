# FastAPI 依赖注入

> 依赖注入就是「函数声明我要什么，FastAPI 负责把东西准备好再塞给我」。共享查询参数、数据库连接、登录校验，全靠它，代码写一遍到处复用。

## 一、什么是依赖注入

### 1.1 生活化类比

路径操作函数声明它运行需要的东西——"依赖"；框架负责执行所有准备工作，把东西"注入"进来。就像去餐厅：你只点菜（声明需求），备菜、炒菜、端上桌全是后厨（框架）的活。

什么时候用得上：

- 共享业务逻辑、数据库连接
- 安全、认证、角色权限检查
- 各种"每个接口都要先干一遍"的事

### 1.2 第一个依赖函数

依赖项就是个普通函数，参数写法和路径操作函数一模一样。先来个简单到没啥用的例子，专注看机制：

```python
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


@app.get("/items/")
async def read_items(commons: Annotated[dict, Depends(common_parameters)]):
    return commons
```

`common_parameters` 就是依赖项：一个没有装饰器的"路径操作函数"，声明了三个可选查询参数（`q`、`skip`、`limit`），返回一个 dict。**不要自己调用它**（别加括号），把函数对象传给 `Depends()` 就行。同一个依赖能服务多个接口（再加个 `/users/` 也一样），共享逻辑只写一遍。

### 1.3 Depends 怎么工作

`commons: Annotated[dict, Depends(common_parameters)]` 和 `Query`、`Body` 一样写在参数位置，但工作方式不同：`Depends()` 只接收一个参数——一个可调用对象（函数、类都行）。收到请求时 FastAPI 自动做三件事：用正确的参数调用 `common_parameters()`（从请求里解析 `q`、`skip`、`limit`），拿到返回结果，赋给路径操作函数的 `commons` 参数。

依赖项声明的所有参数、校验都会合并进 OpenAPI 模式，交互式文档里能看到依赖项带来的查询参数、请求头说明。

### 1.4 用 Annotated 复用依赖

每个接口都完整写一遍 `Annotated[dict, Depends(common_parameters)]` 有点重复，可以存进变量：`CommonsDep = Annotated[dict, Depends(common_parameters)]`，之后参数直接写 `commons: CommonsDep`。这只是标准类型别名，类型信息完整保留，编辑器照常补全、报错，`mypy` 也能用。

### 1.5 async 还是普通 def

依赖项也是 FastAPI 调用的，规则和路径操作函数相同：`async def` 和普通 `def` 随便混——普通 `def` 路径操作里可以声明 `async def` 依赖，反过来也行，FastAPI 知道怎么处理。

依赖注入在不同框架里叫法不同，遇到别懵：资源（resources）、提供方（providers）、服务（services）、可注入（injectables），都是"提供依赖的东西"的不同叫法。

::: info 提示
FastAPI 0.95.0 才开始支持（并推荐）`Annotated`。版本太旧会报错，先升级到 0.95.1+。
:::

## 二、类作为依赖

### 2.1 可调用对象都能当依赖

依赖项的核心要求是**可调用对象**——任何能像函数一样"调用"的东西，Python 类也是（创建实例就是"调用类"）。所以**类能当依赖项**。FastAPI 只关心两件事：是不是可调用对象、声明了哪些参数。类的参数写在 `__init__` 里，处理方式和路径操作函数参数一样。

### 2.2 函数依赖改成类依赖

返回 dict 的痛点：路径操作函数收到 `commons` 后，编辑器完全不知道里面有什么键、什么类型，补全和报错都指望不上。把 `common_parameters` 函数改成 `CommonQueryParams` 类：

```python
class CommonQueryParams:
    def __init__(self, q: str | None = None, skip: int = 0, limit: int = 100):
        self.q = q
        self.skip = skip
        self.limit = limit


@app.get("/items/")
async def read_items(commons: Annotated[CommonQueryParams, Depends(CommonQueryParams)]):
    return {"q": commons.q, "skip": commons.skip, "limit": commons.limit}
```

`__init__` 的参数和原来函数一模一样。FastAPI 执行 `CommonQueryParams(...)`，把实例传给 `commons`，属性用 `commons.q`、`commons.skip` 访问，类型一目了然。

### 2.3 类型注解 vs Depends

`CommonQueryParams` 写了两次，两个位置作用完全不同：

| 位置 | 作用 |
| ---- | ---- |
| `Depends(CommonQueryParams)` | FastAPI 真正用的，决定依赖是什么、调用谁 |
| `Annotated[CommonQueryParams, ...]` | 只是类型提示，FastAPI 不拿它做转换/校验 |

类型注解乱写（`Annotated[Any, ...]`）功能也不受影响，但建议老老实实写，编辑器才有补全。依赖明确是类时 `Depends()` 也能留空，自动拿参数类型当依赖（快捷方式，不习惯就别用）。

## 三、子依赖与缓存

### 3.1 依赖套依赖

依赖项可以再依赖别的依赖项，FastAPI 自动按层级逐个解析，嵌套多深都行。经典例子：请求带 `q` 就用 `q`，没带就退回 cookie 里存的 `last_query`：

```python
from typing import Annotated
from fastapi import Cookie, Depends, FastAPI

app = FastAPI()


def query_extractor(q: str | None = None):
    return q


def query_or_cookie_extractor(
    q: Annotated[str, Depends(query_extractor)],
    last_query: Annotated[str | None, Cookie()] = None,
):
    if not q:
        return last_query
    return q


@app.get("/items/")
async def read_query(query_or_default: Annotated[str, Depends(query_or_cookie_extractor)]):
    return {"q_or_cookie": query_or_default}
```

`query_or_cookie_extractor` 自己是个依赖，同时又声明了另一个依赖：`q` 依赖 `query_extractor` 的返回值，`last_query` 是可选 cookie。路径操作函数里只声明了一个依赖，但 FastAPI 会先解析 `query_extractor`，把结果喂给 `query_or_cookie_extractor`，再把结果注入 `query_or_default`。执行顺序是从叶子到根：先调用最底层的依赖，逐层向上，路径操作函数在收尾。子依赖的参数（查询参数、cookie、请求头……）同样会进 OpenAPI 文档。

### 3.2 同一请求内缓存

同一请求里，同一个依赖被声明多次时（比如两个依赖共用同一个子依赖），FastAPI **只调用一次**，结果缓存，同一请求内复用。好处：数据库连接这类昂贵操作不会重复执行；代价：如果依赖有副作用（每次调用都要"新鲜"的值），缓存会坑你。想要每次重新执行，把 `use_cache` 关掉：

```python
async def needy_dependency(fresh_value: Annotated[str, Depends(get_value, use_cache=False)]):
    return {"fresh_value": fresh_value}
```

| 概念 | 说明 |
| ---- | ---- |
| 子依赖 | 依赖项的参数里再写 `Depends(...)`，形成依赖树 |
| 解析顺序 | 从最底层子依赖开始，逐层向上，到路径操作函数收尾 |
| 缓存 | 同一请求内同一依赖只调用一次，结果复用 |
| `use_cache=False` | 关闭缓存，每次都要新鲜结果 |

## 四、路径操作装饰器与全局依赖

### 4.1 装饰器里的 dependencies

有些依赖只是"要执行"（比如校验请求头），返回值根本用不上。这种依赖别塞进函数参数——会得到一个永远不用的参数，编辑器还可能警告"未使用参数"。放到路径操作装饰器的 `dependencies` 列表里：

```python
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException

app = FastAPI()


async def verify_token(x_token: Annotated[str, Header()]):
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")


async def verify_key(x_key: Annotated[str, Header()]):
    if x_key != "fake-super-secret-key":
        raise HTTPException(status_code=400, detail="X-Key header invalid")
    return x_key


@app.get("/items/", dependencies=[Depends(verify_token), Depends(verify_key)])
async def read_items():
    return [{"item": "Foo"}, {"item": "Bar"}]
```

`read_items` 的参数表干干净净，但请求进来时两个依赖照常执行。三个要点：

- **会执行**：解析方式和普通依赖一样，先子依赖后自身
- **返回值不传递**：`verify_key` 返回了 `x_key`，路径操作函数也收不到
- **能声明需求、能抛异常**：校验失败 `raise HTTPException`，请求直接 400

::: info 提示
例子里用的 `X-Key`、`X-Token` 是自定义请求头。真实项目做安全别自己造轮子，用 FastAPI 内置的安全工具。
:::

### 4.2 全局依赖

想把某个依赖挂到应用的所有接口上，不用一个个装饰器去写。创建 `FastAPI()` 时传 `dependencies` 参数，全应用的路径操作自动生效：

```python
app = FastAPI(dependencies=[Depends(verify_token), Depends(verify_key)])

@app.get("/items/")
async def read_items():
    return [{"item": "Portal Gun"}, {"item": "Plumbus"}]
```

就一处区别：`app = FastAPI(dependencies=[...])` 而不是 `@app.get(..., dependencies=[...])`。启动后不带请求头访问，直接 400，响应体是 `{"detail":"X-Token header invalid"}`。`verify_token` 先执行、`verify_key` 后执行（按列表顺序），全过了才轮到路径操作函数。打开 `/docs` 也能看到两个接口的文档里都自动标出了 `X-Token`、`X-Key` 必填请求头。

### 4.3 三种写法对照

| 声明位置 | 生效范围 | 写法 | 返回值 |
| ---- | ---- | ---- | ---- |
| 函数参数 | 单个路径操作 | `Depends(fn)` | 注入函数 |
| 装饰器 | 单个路径操作 | `@app.get(..., dependencies=[Depends(fn)])` | 不传递 |
| 应用级 | 所有路径操作 | `FastAPI(dependencies=[...])` | 不传递 |

全局依赖和单接口依赖不冲突，是**叠加执行**的关系：请求进来时全部要跑一遍，任何一个抛异常请求就中断。想给一组接口（比如只给 `/admin/` 下）加权限校验，把应用拆成多个文件（APIRouter），在路由层面声明 `dependencies`。

## 五、yield 依赖（资源清理）

### 5.1 yield 的执行时机

普通依赖用 `return` 把值交给路径操作。换成 `yield` 后，一个依赖被拆成两段：

| 代码位置 | 执行时机 |
| ---- | ---- |
| `yield` 之前 | 创建响应之前执行（相当于初始化） |
| `yield` 产出的值 | 注入给路径操作和其他依赖 |
| `yield` 之后 | 响应发送之后执行（相当于清理） |

最经典的场景是数据库会话，把初始化、回滚、关闭一次写全：

```python
async def get_db():
    db = DBSession()
    try:
        yield db
    except Exception:
        db.rollback()
        raise
    finally:
        db.close()
```

`DBSession()` 在请求开始时创建，`db.close()` 在响应发出去之后跑。即使路径操作里抛了异常，`finally` 也保证会话被关掉；不想处理异常，`try/finally` 两行就够了。每个依赖里只能 `yield` 一次，FastAPI 内部就是用 Python 的上下文管理器机制实现的。

### 5.2 子依赖的退出顺序

依赖可以套娃，而且每个都能用 `yield`。`dependency_c` 依赖 `dependency_b`，`dependency_b` 依赖 `dependency_a`，每个都在自己的 `finally` 里关自己的资源。启动顺序 a → b → c，清理顺序反过来——**c 先关，a 收尾**。因为 c 的退出代码里可能还要用 b，b 的退出代码里可能还要用 a。混合 `return` 和 `yield` 的依赖也能任意组合，退出顺序永远正确。用 `yield` 的依赖里写 `try`，还能收到下游抛出的异常：路径操作、其他依赖，任何一处炸了都会传回来。

### 5.3 坑：except 后必须 raise

在 `yield` 依赖里用 `except` 捕获异常后，可以换成自己的异常抛出去，比如 `HTTPException`。大坑：**捕获异常后既不重新抛出、也不抛新异常，FastAPI 会以为一切正常**——客户端看到 500，服务器日志却什么都没有，出了事没法查：

```python
def get_username():
    try:
        yield "Rick"
    except InternalError:
        raise  # 必须 raise，异常不吞，日志可查
```

### 5.4 scope 参数：提前清理

默认情况下，`yield` 后面的退出代码在**响应发送之后**才执行。如果路径操作返回后就不再需要这个依赖，可以在 `Depends` 里加 `scope` 提前关闭：`Depends(get_username, scope="function")`。

scope 取值：`"request"`（默认）在响应发送之后执行退出代码，`"function"` 在路径操作函数返回后、响应发送之前执行。子依赖的 scope 有约束：`"request"` 依赖的子依赖也必须是 `"request"`，`"function"` 的子依赖两种都行。上下文管理器（`with` 对象）也能直接用在 yield 依赖内部。进阶内容，刚开始用可以先跳过，记住 `yield` + `try/finally` 就够用了。
