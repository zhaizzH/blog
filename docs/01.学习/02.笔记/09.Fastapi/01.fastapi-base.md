# FastAPI 基础与请求

> 从装环境到写第一个接口，再到路径参数、查询参数、请求体、更新数据——把 FastAPI 处理请求的完整链路走一遍，全程靠类型标注自动转换、校验、生成文档。

## 一、环境搭建

Python 3.8+ 就行，建议先建虚拟环境，别把包装进系统。

```bash
mkdir fastapi-demo && cd fastapi-demo
python3 -m venv venv
source venv/bin/activate        # Windows 用 venv\Scripts\activate
pip install "fastapi[standard]"
```

`fastapi[standard]` 会带上 uvicorn（运行服务器）和其他开发依赖，一条命令装完。

## 二、第一个应用

### 2.1 Hello World

新建 `main.py`，这是 FastAPI 最简单的完整应用：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def root():
    return {"message": "Hello World"}
```

| 部分 | 作用 |
| ---- | ---- |
| `app = FastAPI()` | 创建应用实例，后面所有路由都挂在它上面 |
| `@app.get("/")` | 装饰器：注册一个 GET 接口，路径是 `/` |
| `async def root()` | 接口处理函数，返回什么客户端就收到什么 |
| `return {"message": ...}` | 返回字典，FastAPI 自动转 JSON |

`return` 的字典没写 `json.dumps`、没设 Content-Type——FastAPI 全包了。返回 Python 对象，它负责序列化成 JSON。

### 2.2 跑起来

```bash
fastapi dev
```

看到 `Uvicorn running on http://127.0.0.1:8000` 就是起来了，浏览器打开 <http://127.0.0.1:8000> 返回 `{"message": "Hello World"}`。

::: info 提示
`fastapi dev` 是开发模式：改代码自动重载，上线用 `fastapi run`。老版本常用 `uvicorn main:app --reload`，效果一样。
:::

### 2.3 自动生成的文档

打开 <http://127.0.0.1:8000/docs>：

| 地址 | 内容 |
| ---- | ---- |
| `/docs` | Swagger UI 交互文档，可点 "Try it out" 直接测试 |
| `/redoc` | ReDoc 文档，另一种风格 |
| `/openapi.json` | OpenAPI 原始定义，机器可读 |

什么都没写就多出三套文档——**代码即文档**是 FastAPI 的核心卖点。OpenAPI 是描述 API 的规范，Swagger UI 只是把它渲染成能点按钮的网页，前端用 openapi-generator 之类的工具也能直接读它生成请求代码。

## 三、路径参数

### 3.1 基本用法

URL 里 `https://xxx/items/3` 这种 `3` 就是路径参数，用 Python 的格式化语法声明：

```python
@app.get("/items/{item_id}")
async def read_item(item_id):
    return {"item_id": item_id}
```

`{item_id}` 会原样作为字符串传给函数。访问 `http://127.0.0.1:8000/items/foo` 返回 `{"item_id": "foo"}`。

### 3.2 类型转换与校验

把 `item_id` 标注成 `int`：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
```

只加 `: int`，FastAPI 就多做两件事：

| 行为 | 说明 |
| ---- | ---- |
| 类型转换 | 访问 `/items/3`，函数收到的是整数 `3`，不是字符串 `"3"` |
| 类型校验 | 访问 `/items/foo`，直接返回 422 错误，不会进函数 |

422 错误响应里 `loc` 精确指出是哪个参数出的问题（`["path", "item_id"]`），前端联调一眼能定位。转换、校验都是 Pydantic 在幕后干的，`str`、`float`、`bool` 和复合类型都能这么标。

### 3.3 顺序很重要

`/users/me`（固定路径）和 `/users/{user_id}`（参数路径）同时存在时，**固定路径必须写在前面**：

```python
# 正确：me 在前面
@app.get("/users/me")
async def read_current_user():
    return {"user_id": "the current user"}

@app.get("/users/{user_id}")
async def read_user(user_id: int):
    return {"user_id": user_id}
```

路由按声明顺序匹配。反着写的话，访问 `/users/me` 时 `{user_id}` 先抢到，把 `"me"` 当 user_id 解析——`int` 接受不了字符串，直接 422。

### 3.4 预设值：枚举

路径参数只允许几个固定值时，用 Python 的 `Enum`：

```python
from enum import Enum

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    return {"model_name": model_name, "message": "深度学习模型"}
```

访问 `/models/lenet` 正常返回，`/models/foo` 返回 422；Swagger 文档里下拉框直接列出三个可选值。继承 `str` 是为了让文档显示字符串值而非整数序号。

## 四、查询参数

### 4.1 什么是查询参数

`http://127.0.0.1:8000/items/?skip=0&limit=10` 里 `?` 之后是查询字符串，键值对用 `&` 分隔。只要函数参数没出现在路径里，FastAPI 就自动把它当成查询参数：

```python
fake_items_db = [{"item_name": "Foo"}, {"item_name": "Bar"}, {"item_name": "Baz"}]

@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):
    return fake_items_db[skip : skip + limit]
```

URL 里的值"本应"是字符串，但标注 `int` 后 FastAPI 先转成整数再传进函数，转不了就 422——和路径参数同一套流程，还白送编辑器补全和 `/docs` 自动列参数。

### 4.2 默认值、可选与必选

查询参数是可选的，还能带默认值——上例 `skip=0`、`limit=10` 就是，访问 `/items/?skip=20` 时 `limit` 仍取默认值。默认值设为 `None`，参数就变可选：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: str, q: str | None = None):
    if q:
        return {"item_id": item_id, "q": q}
    return {"item_id": item_id}
```

`q` 不传就是 `None`。不写默认值就是必选，三类可以混在同一个函数里：

| 参数 | 类型 | 规则 |
| ---- | ---- | ---- |
| `needy` | `str` | 必选，缺了 422，错误里 `loc` 指出 `["query", "needy"]` |
| `skip` | `int` | 默认 `0` |
| `limit` | `int` 或 `None` | 可选 |

### 4.3 bool 参数的"宽容"转换

标注 `bool` 后，一大串常见写法都会被转成 `True`：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: str, q: str | None = None, short: bool = False):
    item = {"item_id": item_id}
    if q:
        item.update({"q": q})
    if not short:
        item.update({"description": "This is an amazing item that has a long description"})
    return item
```

| URL 写法 | `short` 收到的值 |
| ---- | ---- |
| `short=1` / `True` / `true` / `on` / `yes`（任意大小写） | `True` |
| 不传或 `short=0` | `False` |

::: info 提示
路径参数、查询参数可以混着声明很多个，顺序无所谓，FastAPI 按参数名识别来源。查询参数也能用 `Enum` 限制取值范围，写法一样。
:::

## 五、请求体

### 5.1 用 Pydantic 模型声明

请求体 = 客户端发给 API 的数据（比如注册时的用户名密码），用 `POST`（最常见）、`PUT`、`DELETE` 或 `PATCH` 发；`GET` 带请求体规范里没定义行为，别用。

从 `pydantic` 导入 `BaseModel`，定义一个继承它的类：

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.post("/items/")
async def create_item(item: Item):
    return item
```

模型属性规则和查询参数一样：有默认值可选，没默认值必选，`= None` 也算可选。

| 请求体 | 是否有效 |
| ---- | ---- |
| `{"name": "Foo", "description": "An optional description", "price": 45.2, "tax": 3.5}` | 有效（全字段） |
| `{"name": "Foo", "price": 45.2}` | 有效（`description`、`tax` 可选） |
| `{"name": "Foo"}` | 422（缺必选 `price`） |

只靠类型声明，FastAPI 就包办了：按 JSON 读取请求体、转换类型、校验数据、把数据赋值给参数 `item`、生成模型的 JSON Schema 显示在 `/docs` 里。`item` 是 `Item` 类型，编辑器里点属性有补全——收裸 `dict` 就没这待遇。

### 5.2 请求体 + 路径 + 查询参数

```python
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    result = {"item_id": item_id, **item.model_dump()}
    if q:
        result.update({"q": q})
    return result
```

`model_dump()` 把模型转成 dict，方便在响应里拼字段。三类参数的识别规则汇总：

| 函数参数情况 | 数据来源 |
| ---- | ---- |
| 参数也在路径里声明了 | 路径参数 |
| 单一类型（`int`、`float`、`str`、`bool` 等） | 查询参数 |
| Pydantic 模型类型 | 请求体 |

::: info 提示
判断是否必填靠的是默认值 `= None`，不是 `str | None` 标注，但标注还是要写，编辑器靠它做检查。请求体里的单一值（比如裸 `int`）默认会被当成查询参数，要放进请求体得用 `Body`——那是参数校验篇的内容。
:::

## 六、更新数据：PUT 与 PATCH

### 6.1 PUT：整体替换

`PUT` 的语义是"用这份新数据替换旧数据"，请求体里得带完整字段。存库前用 `jsonable_encoder` 把模型转成可序列化格式——比如把 `datetime` 转成 `str`：

```python
from fastapi.encoders import jsonable_encoder

class Item(BaseModel):
    name: str | None = None
    description: str | None = None
    price: float | None = None
    tax: float = 10.5
    tags: list[str] = []

items = {"foo": {"name": "Foo", "price": 50.2}, "bar": {"name": "Bar", "price": 62, "tax": 20.2}}

@app.put("/items/{item_id}")
async def update_item(item_id: str, item: Item):
    items[item_id] = jsonable_encoder(item)
    return items[item_id]
```

替换的坑：把 `bar` 更新成 `{"name": "Barz", "price": 3, "description": null}`，请求体里没带 `tax`，输入模型就取了默认值 `10.5`，把原本存的 `20.2` 悄悄覆盖了。这是整体替换的代价：模型里所有带默认值的字段，你没传就等于传了默认值。

### 6.2 PATCH：部分更新

`PATCH` 的语义是"只改你传的那些字段，其余保持原样"。核心是 `item.model_dump(exclude_unset=True)`——只输出创建模型时**显式设置**过的字段，默认值不算数：

```python
@app.patch("/items/{item_id}")
async def update_item(item_id: str, item: Item) -> Item:
    stored_item_data = items[item_id]
    stored_item_model = Item(**stored_item_data)        # 旧数据还原成模型
    update_data = item.model_dump(exclude_unset=True)   # 只留显式传过的字段
    updated_item = stored_item_model.model_copy(update=update_data)  # 旧模型上打补丁
    items[item_id] = jsonable_encoder(updated_item)
    return updated_item
```

请求体只发 `{"name": "Barz"}`，`update_data` 就只有它，`tax` 压根不在里面，旧值 20.2 保住了。完整流程：取旧数据 → 还原成模型 → `exclude_unset` 生成"只含显式传过的字段"的 dict → `model_copy(update=...)` 打补丁 → `jsonable_encoder` 转格式 → 存回数据库。`PATCH` 没有 `PUT` 出名，很多团队干脆只用 `PUT` 干部分更新的活——`PUT` 也能用这套 `exclude_unset` 技巧。

### 6.3 前提：模型得全可选

部分更新时输入模型**仍然会被校验**，想让"只传一个字段"合法，模型的每个字段都得是可选（有默认值或 `None`）。更新模型（全可选）和创建模型（必填）是两套约束，别硬塞进同一个模型：创建用必填模型，更新用全可选模型。

| 方法 | 语义 | 请求体 | 风险 |
| ---- | ---- | ---- | ---- |
| `PUT` | 整体替换 | 要带完整数据 | 没传的默认值字段会覆盖旧值 |
| `PATCH` | 局部修补 | 只带要改的字段 | 需要 `exclude_unset` + `model_copy` 配合 |
