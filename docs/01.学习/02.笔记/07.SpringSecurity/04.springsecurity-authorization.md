# Spring Security 授权与权限控制

授权（Authorization）是权限验证的过程，即系统确认"你能做什么"。Demo-Security 项目采用 ==URL 层面 + 方法层面== 的双重授权机制，结合自定义异常处理，实现精细化的权限控制。

## Security 配置

`SecurityConfig` 是整个安全配置的核心，定义了过滤器链、授权规则和异常处理：

```java
@Configuration
@EnableMethodSecurity(securedEnabled = true)
public class SecurityConfig {

    @Resource
    private JwtAuthenticationTokenFilter jwtAuthenticationTokenFilter;
    @Resource
    private LoginUnAccessDeniedHandler loginUnAccessDeniedHandler;
    @Resource
    private LoginUnAuthenticationEntryPointHandler loginUnAuthenticationEntryPointHandler;
    @Resource
    private LogoutStatusSuccessHandler logoutStatusSuccessHandler;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity httpSecurity) throws Exception {
        httpSecurity
                // 1. 禁用 CSRF（前后端分离架构不需要）
                .csrf(AbstractHttpConfigurer::disable)

                // 2. 无状态会话策略
                .sessionManagement(session -> session
                        .sessionCreationPolicy(SessionCreationPolicy.STATELESS))

                // 3. URL 授权规则
                .authorizeHttpRequests(authorize -> authorize
                        .requestMatchers("/login", "/logout", "/test1").permitAll()
                        .anyRequest().authenticated())

                // 4. 异常处理
                .exceptionHandling(ex -> ex
                        .authenticationEntryPoint(loginUnAuthenticationEntryPointHandler)
                        .accessDeniedHandler(loginUnAccessDeniedHandler))

                // 5. 注册 JWT 过滤器
                .addFilterBefore(jwtAuthenticationTokenFilter,
                        UsernamePasswordAuthenticationFilter.class)

                // 6. 注销配置
                .logout(logout -> logout
                        .logoutUrl("/logout")
                        .logoutSuccessHandler(logoutStatusSuccessHandler));

        return httpSecurity.build();
    }
}
```

### URL 授权规则说明

| 规则 | 说明 |
|------|------|
| `.requestMatchers("/login", "/logout", "/test1").permitAll()` | 无需认证即可访问 |
| `.anyRequest().authenticated()` | 其他请求必须认证 |

> ==注意：== `.requestMatchers("/login")` 较新的 API 已替代过时的 `.antMatchers()` 和 `.mvcMatchers()`。

## 方法级授权

项目通过 `@EnableMethodSecurity(securedEnabled = true)` 启用方法级安全注解，然后使用 `@PreAuthorize` 对 Controller 方法进行权限控制：

```java
@RestController
@RequestMapping("/test")
public class HelloController {

    // 无需认证 —— 公开接口
    @GetMapping("/test1")
    public String test1() {
        return "test1";
    }

    // 仅需认证，不限制角色
    @GetMapping("/test2")
    public String test2() {
        return "test2";
    }

    // 需要 admin 角色
    @PreAuthorize("hasRole('admin')")
    @GetMapping("/test3")
    public String test3() {
        return "test3";
    }

    // 需要 admin 或 CEO 角色（满足其一即可）
    @PreAuthorize("hasAnyRole('admin','CEO')")
    @GetMapping("/test4")
    public String test4() {
        return "test4";
    }

    // 需要同时拥有 CTO 和 CEO 角色
    @PreAuthorize("hasRole('CTO') and hasRole('CEO')")
    @GetMapping("/test5")
    public String test5() {
        return "test5";
    }

    // 需要 user:add 权限
    @PreAuthorize("hasAuthority('user:add')")
    @GetMapping("/test6")
    public String test6() {
        return "test6";
    }

    // 需要 user:add 或 user:del 权限（满足其一即可）
    @PreAuthorize("hasAnyAuthority('user:add','user:del')")
    @GetMapping("/test7")
    public String test7() {
        return "test7";
    }

    // 需要同时拥有 user:add 和 user:del 权限
    @PreAuthorize("hasAuthority('user:add') and hasAuthority('user:del')")
    @GetMapping("/test8")
    public String test8() {
        return "test8";
    }
}
```

### @PreAuthorize 表达式汇总

| 表达式 | 说明 |
|--------|------|
| `hasRole('admin')` | 当前用户拥有 `admin` 角色 |
| `hasAnyRole('admin','CEO')` | 当前用户拥有 admin **或** CEO 角色 |
| `hasRole('CTO') and hasRole('CEO')` | 当前用户 **同时** 拥有 CTO 和 CEO 角色 |
| `hasAuthority('user:add')` | 当前用户拥有 `user:add` 权限 |
| `hasAnyAuthority('user:add','user:del')` | 当前用户拥有 user:add **或** user:del 权限 |
| `hasAuthority('user:add') and hasAuthority('user:del')` | 当前用户 **同时** 拥有 user:add 和 user:del 权限 |
| `permitAll()` | 始终允许访问 |
| `denyAll()` | 始终拒绝访问 |
| `isAuthenticated()` | 用户已认证（包括记住我） |
| `isFullyAuthenticated()` | 用户已完整认证（非记住我） |

## 角色与权限的区别

在 Spring Security 中，**角色**和**权限**在底层都是通过 `GrantedAuthority` 实现的，它们的区别在于前缀约定的不同：

| 特性 | 角色（Role） | 权限（Authority） |
|------|------|------|
| 存储前缀 | `ROLE_`（自动添加） | 无前缀 |
| 数据库示例 | `admin`、`CEO` | `user:add`、`user:del` |
| 表达式 | `hasRole('admin')` | `hasAuthority('user:add')` |
| 匹配规则 | 添加 `ROLE_` 前缀后比较 | 直接比较 |

实现原理见 `LoginUserDetails.getAuthorities()`：

```java
@Override
public Collection<? extends GrantedAuthority> getAuthorities() {
    List<GrantedAuthority> authorities = new ArrayList<>();

    // 角色 —— 添加 ROLE_ 前缀
    for (String roleName : roleNames) {
        authorities.add(new SimpleGrantedAuthority("ROLE_" + roleName));
    }

    // 权限 —— 直接使用权限标识
    for (String permissionName : permissionNames) {
        authorities.add(new SimpleGrantedAuthority(permissionName));
    }
    return authorities;
}
```

## 统一异常处理

### 授权拒绝处理器

当用户已登录但权限不足时触发（HTTP 403）：

```java
@Component
public class LoginUnAccessDeniedHandler implements AccessDeniedHandler {

    @Override
    public void handle(HttpServletRequest request, HttpServletResponse response,
                       AccessDeniedException accessDeniedException) throws IOException {
        response.setContentType("application/json;charset=utf-8");
        response.getWriter().write(
                JSONUtil.toJsonStr(new Result(-1, "权限不足,请重新授权。", null)));
    }
}
```

### 未认证处理器

当用户未登录或 Token 过期时触发（HTTP 401）：

```java
@Component
public class LoginUnAuthenticationEntryPointHandler implements AuthenticationEntryPoint {

    @Override
    public void commence(HttpServletRequest request, HttpServletResponse response,
                         AuthenticationException authException) throws IOException {
        response.setContentType("application/json;charset=utf-8");
        response.getWriter().write(
                JSONUtil.toJsonStr(new Result(-1, "用户未认证或登录已过期，请重新登录后再访问", null)));
    }
}
```

### 异常场景对照

| 场景 | 触发点 | 响应状态 | 提示信息 |
|------|--------|----------|----------|
| 未携带 Token 访问需认证接口 | `AuthenticationEntryPoint` | - | 用户未认证或登录已过期，请重新登录后再访问 |
| Token 过期 | `AuthenticationEntryPoint` | - | 同上 |
| 已登录但角色/权限不足 | `AccessDeniedHandler` | - | 权限不足，请重新授权。 |
| 登录密码错误 | `LoginService` catch | 500 | 认证失败，用户名或密码错误 |
| 注销成功 | `LogoutStatusSuccessHandler` | 200 | 注销成功 |

> ==注意：== 所有异常响应都返回 JSON 格式，确保前后端分离架构中前端可以统一处理错误信息。

## 统一响应对象

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Result {
    private int code;
    private String msg;
    private Object data;

    public Result(int code, String msg) {
        this.code = code;
        this.msg = msg;
    }
}
```

该对象贯穿整个项目的请求响应，格式统一，便于前端进行全局响应拦截处理。
