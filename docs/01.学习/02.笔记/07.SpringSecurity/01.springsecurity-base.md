# Spring Security 基础

总结 SpringSecurity 笔记，基于 Spring Boot 3 + Spring Security Demo 项目实现 ==RBAC（基于角色的访问控制）== 权限管理，包含 JWT 认证、Redis 缓存、MyBatis 持久化等完整技术栈。

## 项目简介

**Demo-Security** 是一个基于 Spring Boot 3 的安全权限管理演示项目，采用经典的 RBAC 权限模型，整合 Spring Security + JWT + Redis + MyBatis，实现了一套完整的认证与授权体系。

### 项目结构

```
top.zhaizz
  ├── common              # 公共类（统一响应 Result）
  ├── config              # 配置类（SecurityConfig）
  ├── controller          # REST 控制器
  ├── entity              # 数据库实体（User、Role、Permission 等）
  ├── mapper              # MyBatis 映射器接口
  ├── security            # Spring Security 核心组件
  ├── service             # 业务逻辑服务
  └── util                # 工具类（JWT、Redis）
```

## RBAC 权限模型

**RBAC（Role-Based Access Control）** 即基于角色的访问控制，通过 ==用户→角色→权限== 的层级关系来管理访问权限。

### 核心概念

- **用户（User）**：系统的使用者，一个用户可以拥有多个角色
- **角色（Role）**：权限的集合，一个角色可以包含多个权限，也可以分配给多个用户
- **权限（Permission）**：系统的最小操作单元，如 `user:add`、`user:del` 等

### 数据模型关系

```
用户 ──（多对多）── 角色 ──（多对多）── 权限
```

整个项目的数据库设计围绕五张表展开：

- `user`：用户表
- `role`：角色表
- `permission`：权限表
- `user_role`：用户-角色关联表
- `role_permission`：角色-权限关联表

## 认证与授权概要

Demo-Security 项目的认证授权流程可以概括为以下步骤：

1. **用户登录**：用户通过手机号和密码登录，服务器验证身份后颁发 JWT Token
2. **Token 校验**：客户端每次请求携带 Token，服务端通过过滤器校验 Token 有效性
3. **权限验证**：Spring Security 通过 `@PreAuthorize` 注解对接口进行权限控制
4. **数据缓存**：用户认证信息存储在 Redis 中，实现无状态服务和及时注销

| 步骤 | 组件 | 功能 |
|------|------|------|
| 登录认证 | `LoginService` + `AuthenticationManager` | 验证用户名密码，生成 Token |
| Token 签发 | `JwtUtils` | 使用 HMAC256 算法生成 JWT |
| 会话缓存 | `RedisClient` | 将用户信息缓存到 Redis |
| 请求过滤 | `JwtAuthenticationTokenFilter` | 每次请求校验 Token，解析用户 |
| 权限控制 | `SecurityConfig` + `@PreAuthorize` | URL 和方法级别的权限拦截 |
| 异常处理 | `AuthenticationEntryPoint` + `AccessDeniedHandler` | 统一的认证/授权异常响应 |
| 注销 | `LogoutStatusSuccessHandler` | 清除 Redis 中的会话信息 |
