# DataLoom 总结

> 本文档是对 [DataLoom](https://github.com/DevYangJC/DataLoom) 在线协作编辑项目的完整梳理,原作者 [GitHub](https://github.com/DevYangJC)，涵盖系统架构、模块设计、数据分块策略、Luckysheet 集成、前后端交互流程及关键实现细节。适合深入了解项目实现后查阅。

## 1. 项目总览

DataLoom 是一个基于 **Spring Boot + Vue 3** 的 Excel 在线协作编辑平台，支持十万级数据量的 Excel 文件上传、在线编辑和导出。

### 1.1 技术栈

| 板块 | 技术选型 | 版本 |
|------|----------|------|
| 后端框架 | Spring Boot | 3.5.15 |
| ORM | MyBatis + PageHelper | 3.0.5 / 1.4.3 |
| 数据库 | MySQL | — |
| Excel 解析 | Apache POI | 5.4.0 |
| Excel 导出 | EasyExcel / ExcelJS | 2.2.11 / 4.4.0 |
| 前端框架 | Vue 3 + Vite | 6.0.7 |
| UI 组件库 | Element Plus | 2.10.7 |
| 在线表格 | Luckysheet | 2.1.13 |
| API 文档 | Knife4j (Swagger) | 3.0.2 |
| 工具库 | Lombok / FastJSON / AOP | — |

### 1.2 核心能力

| 功能 | 说明 |
|------|------|
| 文件上传 | 支持 `.xlsx` / `.xls`，流式解析后分块入库 |
| 在线编辑 | Luckysheet 提供类 Excel 编辑体验，编辑后增量保存 |
| 保存策略 | 结构变更走全量快照，纯数据变更走增量更新 |
| 图片/图表 | 支持插入图片、图表（ECharts 兜底恢复） |
| 文档管理 | 分页列表、重命名、软删除 |
| 导出 | 客户端 ExcelJS 导出为 `.xlsx` 文件 |

## 3. 数据模型设计

### 3.1 核心实体关系

```
ExcelDocument ──1:N──→ ExcelSheet ──1:N──→ ExcelSheetChunk
   (元数据)              (Sheet 配置)        (单元格数据分块)
```

### 3.2 ExcelDocument（文档主表）

存储文档的元数据，**不含任何单元格数据**。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 主键 |
| `name` | String | 文档名称 |
| `sheet_count` | Integer | Sheet 数量 |
| `sheet_names` | String | Sheet 名称列表 JSON |
| `version` | Long | 乐观锁版本号 |
| `status` | Integer | 1=正常, 2=回收站, 3=已删除 |
| `file_path` | String | 原始文件本地路径 |
| `file_size` | Long | 文件大小（字节） |
| `create_time` / `update_time` | LocalDateTime | 时间戳 |

### 3.3 ExcelSheet（Sheet 配置表）

存储每个 Sheet 页签的配置信息，**不存储单元格数据**。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 主键 |
| `document_id` | Long | 所属文档 ID |
| `sheet_index` | Integer | 在 Workbook 中的下标（0 起始） |
| `sheet_name` | String | Sheet 名称 |
| `total_rows` / `total_cols` | Integer | 行列数 |
| `chunk_count` | Integer | 分块数量 |
| `config_json` | String | Luckysheet 完整 config（merge/columnlen/rowlen） |
| `merge_config_json` | String | 合并单元格配置 |
| `column_len_json` / `row_len_json` | String | 列宽 / 行高配置 |
| `hyperlink_config_json` | String | 超链接配置 |
| `images_config_json` | String | 图片配置（Base64） |
| `condition_format_json` | String | 条件格式配置 |
| `chart_json` | String | 图表配置 |
| `active` | Integer | 是否为活动 Sheet |

### 3.4 ExcelSheetChunk（数据分块表）

单元格数据分块存储，**每块含约 1000 行的 celldata**。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 主键 |
| `document_id` | Long | 所属文档 ID（冗余） |
| `sheet_id` | Long | 所属 Sheet ID |
| `chunk_index` | Integer | 块序号 |
| `row_start` / `row_end` | Integer | 该块包含的行范围 |
| `celldata_json` | String | Luckysheet 兼容的单元格数据 JSON |

> **设计考量**：十万级数据若整体存为一条 CLOB/TEXT，单行可达数十 MB。分块后单块 JSON 通常在几百 KB 以内，可按需加载。

## 4. 分层架构详解

### 4.1 Controller 层

两个 Controller，遵循 RESTful 设计：

**ExcelFileController** — 文件上传入口
- `POST /api/excel/upload` — 上传 Excel 文件，返回文档 ID 和 Sheet 元信息

**ExcelDocumentController** — 文档 CRUD
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/excel/document/list` | 分页文档列表 |
| GET | `/api/excel/document/{id}` | 文档详情（含 Sheet 配置，不含 celldata） |
| GET | `/api/excel/document/{id}/sheet/{sheetId}/all` | 加载 Sheet 全部 celldata |
| PUT | `/api/excel/document/{id}/cells/batch` | 批量增量更新单元格 |
| PUT | `/api/excel/document/{id}/name` | 重命名文档 |
| DELETE | `/api/excel/document/{id}` | 删除文档 |

### 4.2 Service 层

**ExcelDocumentServiceImpl** — 核心业务
- `create()` — 文件上传 → 本地存储 → POI 流式解析 → 分块写入数据库
- `list()` — PageHelper 分页查询
- `deleteDocument()` — 事务控制：软删除文档 + Sheet + 物理删除 Chunk

**ExcelSheetServiceImpl** — Sheet 管理
- `detail()` — 查询文档详情，将各 Sheet 的 config/merge/图片/图表等组装为统一 VO
- `saveSheetMeta()` — 解析 Sheet 的合并单元格、列宽、行高等配置并保存

**ExcelSheetChunkServiceImpl** — 数据分块核心
- `saveSheetChunks()` — 按 1000 行/块，流式读取 POI 行数据写入数据库
- `loadAllCelldata()` — 合并所有 Chunk 的 celldata 返回
- `batchUpdateCells()` — 按 Chunk 分组，只更新涉及变动的数据块

### 4.3 公共模块

**`Result<T>`** — 统一响应
```json
{"code": 200, "success": true, "message": "success", "data": {...}}
```

**AutoFill AOP** — 时间自动填充
- `@AutoFill(INSERT)` → 自动设置 `createTime` 和 `updateTime`
- `@AutoFill(UPDATE)` → 自动设置 `updateTime`
- 通过反射调用 Lombok 生成的 getter/setter，**仅当字段为 null 时才填充**

## 5. 文件上传与解析流程

### 5.1 完整流程

```
上传 .xlsx 文件
    │
    ├─ 1. 文件校验（非空、.xlsx/.xls 后缀）
    ├─ 2. UUID 重命名保存到本地磁盘
    ├─ 3. 插入 excel_document 主记录
    ├─ 4. POI 流式解析每个 Sheet
    │      ├─ 保存 Sheet 元信息（合并单元格、列宽、行高等）
    │      └─ 逐行遍历，按 1000 行/块写入 excel_sheet_chunk
    └─ 5. 更新文档的 sheetCount / sheetNames
```

### 5.2 单元格数值解析（`buildCellValue`）

POI 的 Cell 类型映射：

| POI CellType | Luckysheet 格式 | 说明 |
|--------------|-----------------|------|
| STRING | `{t:"s", fa:"General"}` | 字符串 |
| NUMERIC（日期） | `{t:"d", fa:"yyyy-MM-dd"}` | 日期格式 |
| NUMERIC（数字） | `{t:"n", fa:"General"}` | 通用数字 |
| BOOLEAN | `{t:"b"}` | 布尔值 |
| FORMULA | `{f:"=...", t:"n"}` | 公式（含计算结果） |

### 5.3 分块策略

分块大小：**1000 行/块**（`CHUNK_SIZE = 1000`）

```
行 0 ~ 999   → Chunk 0
行 1000 ~ 1999 → Chunk 1
行 2000 ~ 2999 → Chunk 2
...
```

- 写入时使用 `buffer` 积累当前块的行数据，达到阈值或遍历结束时批量 INSERT
- 更新时先定位行号所属的 Chunk，然后按需替换/追加单元格

## 6. 在线编辑与保存策略

### 6.1 Luckysheet 初始化

前端 `SheetEditor.vue` 的初始化流程：

```
加载文档结构 → 加载各 Sheet 元信息
    │
    ├─ fetchSheetCelldata(meta) → 取回所有 Chunk 合并的 celldata
    │
    ├─ buildInitialSheets(metas) → 组装 Luckysheet 兼容数据结构
    │
    └─ initLuckysheet(sheets) → 调用 luckysheet.create()
```

### 6.2 双模式保存策略

前端通过**结构快照对比**决定保存方式：

**① 结构变更 → 全量快照保存**
- 触发条件：Sheet 增删/重命名、合并单元格、图片、图表、超链接、条件格式变化
- 调用 `saveWorkbook()` → 后端全量替换所有 Sheet 的 Chunk 数据
- 后端返回新的 `sheetIdMap`，前端刷新映射

**② 纯单元格变更 → 增量更新**
- 触发条件：仅单元格值变化
- 调用 `batchUpdateCells()` → 后端按 Chunk 分组，只更新受影响的分块

### 6.3 图表保存的四步策略

`serializeWorkbook()` 中的图表保真策略：

```
Step 1: ECharts 实例兜底
    └─ 从 DOM 中已渲染的 ECharts 实例提取 chartOptions

Step 2: 清理僵尸 chart
    └─ 过滤掉没有有效 chartOptions 的 chart 项

Step 3: chartmix 原生格式刷新
    └─ 调用 getluckysheetfile(true) 用原生格式覆盖 chartOptions

Step 4: 最终序列化
    └─ 只保留有有效 chart_id + chartOptions 的图表
```

## 7. 导出实现

导出通过 **ExcelJS** 在客户端完成：

```
Luckysheet data
    │
    ├─ applyDimensions() → 列宽 / 行高映射
    ├─ applyCells() → 单元格值 + 字体 + 对齐 + 填充
    ├─ applyMerges() → 合并单元格还原
    ├─ applyBorders() → 边框样式还原
    │
    └─ workbook.xlsx.writeBuffer() → FileSaver 下载
```

支持字体映射（微软雅黑、宋体、黑体等 13 种）、颜色转换（RGB/Hex → ARGB）、边框样式映射（14 种 POI 样式）。

- 快捷键支持（Delete/Backspace 标记脏数据）

## 11. 关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 数据分块 | 1000 行/块 | 避免单行 CLOB 过大，支持十万级数据按需加载 |
| 保存策略 | 双模式（增量/全量） | 纯数据变更走增量避免全量重建 Chunk，结构变更走全量保证一致性 |
| 图片删除 | DOM + Memory 双重 | 同时从 DOM 移除和数据内存清理，防止 ghost 残留 |
| 图表恢复 | ECharts 兜底 → 清理僵尸 → chartmix 刷新 → 序列化 | 解决 chartmix 插件在 chartOptions 丢失时的崩溃问题 |
| AOP 时间填充 | 反射 + 注解 | 统一时间管理，避免每个 Mapper 方法手动设置 |
| 前端结构快照 | 稳定 JSON 签名对比 | 高效检测 config/images/chart 等是否变更，辅助保存策略选择 |
